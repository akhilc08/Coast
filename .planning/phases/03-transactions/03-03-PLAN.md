2. **Create `lib/fulfillment.ts`** — orchestrates post-payment document pipeline:
   - Export `generateAndSendDocuments(orderId: string): Promise<void>`
   - Steps:
     a. Fetch order with listing and buyer/seller profiles from DB (admin client)
     b. Generate purchase agreement PDF: `generatePurchaseAgreement({...})`
     c. Generate bill of sale PDF: `generateBillOfSale({...})`
     d. Upload both PDFs to `order-documents` bucket: storage key pattern `{orderId}/purchase-agreement.pdf` and `{orderId}/bill-of-sale.pdf`
     e. Update `order_documents` rows with `storage_key` values
     f. Send to Dropbox Sign: create signature request with both files, buyer as signer
        - IMPORTANT: Suppress Dropbox Sign's native email to signer. Use `isForEveryone: false` or SDK-specific suppression flag. If SDK doesn't support it, log a warning but proceed (Open Question #1 from RESEARCH.md)
     g. Store `esign_ref` (signature_request_id) on both `order_documents` rows
     h. Update `order_documents` status to 'sent'
     i. Update `orders.status` to 'documents_sent'
     j. Send NOTF-03 email (signing request notification) via Resend, pointing buyer to `/account/orders/{orderId}`
   - Wrap entire pipeline in try/catch — log errors, do not throw (fire-and-forget from webhook)

3. **Create `app/api/webhooks/dropbox-sign/route.ts`** — Dropbox Sign callback:
   - `export async function POST(request: Request)`
   - Parse `multipart/form-data`: `const formData = await request.formData()`, then `JSON.parse(formData.get('json') as string)`
   - Verify event hash: `createHmac('sha256', DROPBOX_SIGN_API_KEY).update(event_time + event_type).digest('hex')` — return 401 if mismatch
   - Handle `signature_request_all_signed`:
     a. Get `signature_request_id` from payload
     b. Find `order_documents` rows by `esign_ref = signature_request_id` (admin client)
     c. Find associated order
     d. Download signed files from Dropbox Sign API (use `signatureApi.signatureRequestFiles(signatureRequestId, { fileType: 'pdf' })`)
     e. Upload signed PDFs to `order-documents` bucket with `-signed` suffix: `{orderId}/purchase-agreement-signed.pdf`
     f. Update `order_documents`: status = 'signed', signed_at = now(), storage_key = signed path
     g. Update `orders.status` to 'documents_signed' (or 'complete')
     h. Send NOTF-04 email via Resend with signed PDFs as attachments (download buffers from Supabase Storage for attachment)
   - CRITICAL: Return `new Response('Hello API Event Received', { status: 200 })` — exact text required by Dropbox Sign

4. **Wire fulfillment into Stripe webhook** — Update `app/api/webhooks/stripe/route.ts`:
   - Import `generateAndSendDocuments` from `@/lib/fulfillment`
   - Import `after` from `next/server`
   - Replace the `// TODO Plan 03` placeholder with: `after(async () => { await generateAndSendDocuments(order.id) })`
   - This ensures document generation runs after the webhook response is sent (within Vercel's extended execution time)
