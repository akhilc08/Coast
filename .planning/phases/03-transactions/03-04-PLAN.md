   - Query orders: `.from('orders').select('*, listings(id, title, year, make, model, vin, price_cents, photos:listing_photos(storage_key))').eq('buyer_id', user.id).order('created_at', { ascending: false })`

   - Render page with dark theme (bg-zinc-950):
     - "My Orders" heading
     - If no orders: empty state "You haven't made any purchases yet." with link to browse listings
     - Grid of order cards (1 col mobile, 2 cols lg):
       - Each card uses `Card` component from shadcn
       - Vehicle photo (first photo from listing_photos, use Supabase storage public URL from car-photos bucket — these are public)
       - Vehicle: `{year} {make} {model}`
       - Price: formatted from `price_cents`
       - Date: formatted `created_at`
       - Status badge: color-coded by order status
         - `paid` → yellow badge "Paid"
         - `documents_sent` → blue badge "Documents Sent"
         - `documents_signed` → green badge "Signed"
         - `complete` → green badge "Complete"
         - `cancelled` → red badge "Cancelled"

<task type="auto">
  <name>Task 2: Order detail page with document access and signing links</name>
  <files>app/account/orders/[orderId]/page.tsx, app/actions/orders.ts</files>
  <action>
1. **Create `app/actions/orders.ts`** — Server actions for document access:
   - `'use server'` directive
   - `export async function getOrderDocumentUrl(documentId: string): Promise<string>`:
     - Authenticate user via `createClient().auth.getUser()`
     - Fetch document from `order_documents` with order join to verify buyer_id matches user.id
     - If no document or unauthorized, throw error
     - If `storage_key` is null, throw "Document not yet generated"
     - Use `createAdminClient()` to generate signed URL: `.storage.from('order-documents').createSignedUrl(storageKey, 3600)` (1 hour expiry)
     - Return the signed URL

2. **Create `app/account/orders/[orderId]/page.tsx`** — Order detail page:
   - Server Component — receives `params.orderId`
   - Fetch order: `.from('orders').select('*, listings(id, title, year, make, model, vin, mileage, exterior_color, price_cents), order_documents(*), profiles!orders_seller_id_fkey(business_name)').eq('id', orderId).single()`
   - RLS enforces buyer can only see own orders
   - If no order, redirect to `/account/orders`
   - Dark theme layout matching purchase history:
     - Back link to "My Orders"
     - Order header: "Order #{first 8 chars of id}" + status badge
     - Vehicle section: year make model, VIN, mileage, color
     - Payment section: amount paid, date
     - Seller: business name
     - **Documents section**: for each `order_document`:
       - Document type label ("Purchase Agreement" / "Bill of Sale")
       - Status badge (pending/sent/signed)
       - If status is 'signed' and storage_key exists: "Download" button that calls `getOrderDocumentUrl` server action and opens the signed URL
       - If status is 'sent': "Awaiting Signature" text with subtle animation (pulse dot)
       - If status is 'pending': "Being Prepared" text
     - **Signing section** (if any documents have status 'sent'):
       - Message: "Your documents are ready to sign. Click below to review and sign."
       - Note: The actual signing happens via the Dropbox Sign embedded URL or link. For v1, the signing link will be provided via NOTF-03 email. On this page, show the status and a note: "Check your email for the signing link, or it will appear here when ready."
       - If `esign_ref` exists on documents, a future enhancement could embed the Dropbox Sign signing URL — for now, direct to email
  </action>

  </verify>
